# Frontend Internationalization (zh-CN + English) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-introduce two-language support (Simplified Chinese + English) to the React frontend by extending the existing homegrown `t()` into a Zustand-backed, reactive system, and migrating every remaining hardcoded Chinese UI string to translation keys so English is fully covered.

**Architecture:** A new Zustand locale store (`web/src/store/locale.ts`) holds the active `lang` ('zh-CN' | 'en'), persisted to `localStorage`, detected from `navigator.language` on first run with a `zh-CN` default. `web/src/locales/index.ts` resolves the active language's messages via `t(key, params)` (dotted lookup + `{param}` interpolation + zh-CN/key fallback) and exposes `useTranslation()` so components re-render on language switch; plain `t()` stays usable from non-component modules. Two mirrored JSON catalogs (`zh-CN.json`, `en.json`) hold every key. A language selector lives in 其他设置 (Misc Settings). The backend is untouched (already English).

**Tech Stack:** React 19 + MUI 9 + Zustand + Vite + Vitest + Biome; Go (gin) backend (unchanged).

**Spec:** `docs/superpowers/specs/2026-07-09-i18n-design.md`

## Conventions (read first)

- **Commit policy:** Per project `CLAUDE.md`/`AGENTS.md`, do **not** commit/stage/push unless the user explicitly asks. The "Checkpoint" steps below mean: run the verification command, then leave the change in the working tree. Do not run `git commit`.
- **Indentation:** Frontend TS/TSX uses **4 spaces**; JSON uses 4-space via Biome. (No Go changes in this plan.)
- **Reactivity rule (apply everywhere):**
  - In any **React component or custom hook that is part of the render tree**, obtain translations via `const { t } = useTranslation()` (imported from `@/locales`) and use that `t` for *both* JSX text and event-handler messages. This is what re-renders on language switch.
  - In **plain non-component modules** (`web/src/api/*`, `web/src/store/*`, `web/src/utils/*`), use the plain `t()` (imported from `@/locales`) — it reads the current language from the store at call time and needs no hook.
- **Whole-project gate (run at the end and whenever a phase finishes):** `make fmt && make check && make test && git diff --check`.
- **Residual-Chinese gate (the objective "migration complete" test):**
  ```bash
  grep -rnP '[\x{4e00}-\x{9fff}]' web/src --include='*.tsx' --include='*.ts' \
    | grep -v '/locales/' | grep -v '\.test\.' | grep -vE ':\s*//' | grep -vE ':\s*\*'
  ```
  This MUST print nothing before the plan is done (Chinese is allowed only inside `web/src/locales/*.json`, inside `*.test.*` files, and in `//` or `*` comments).

```ts
import { create } from 'zustand'

export type Lang = 'zh-CN' | 'en'

export interface LocaleState {
    lang: Lang
    setLang: (lang: Lang) => void
}

const STORAGE_KEY = 'homelab-lang'
const SUPPORTED: Lang[] = ['zh-CN', 'en']

export function detectInitialLang(): Lang {
    try {
        const stored = localStorage.getItem(STORAGE_KEY)
        if (stored && SUPPORTED.includes(stored as Lang)) return stored as Lang
    } catch {
        // localStorage unavailable (private mode / disabled) — fall through
    }
    const nav = typeof navigator !== 'undefined' ? navigator.language : ''
    if (!nav) return 'zh-CN'
    return nav.toLowerCase().startsWith('zh') ? 'zh-CN' : 'en'
}

export const useLocaleStore = create<LocaleState>((set) => ({
    lang: detectInitialLang(),
    setLang: (lang) => {
        try {
            localStorage.setItem(STORAGE_KEY, lang)
        } catch {
            // ignore write failure — keep the choice in-memory for this session
        }
        set({ lang })
    },
}))
```

```ts
import { useLocaleStore, type Lang } from '@/store/locale'

import en from './en.json'
import zhCN from './zh-CN.json'

type MessageMap = Record<string, unknown>
type MessageParams = Record<string, string | number | boolean | null | undefined>

const messages: Record<Lang, MessageMap> = {
    'zh-CN': zhCN,
    en,
}

export interface LanguageOption {
    code: Lang
    label: string
}

export const LANGUAGES: LanguageOption[] = [
    { code: 'zh-CN', label: '中文' },
    { code: 'en', label: 'English' },
]

function resolve(map: MessageMap, key: string): string {
    const value = key.split('.').reduce<unknown>((acc, name) => {
        if (typeof acc === 'object' && acc !== null) return (acc as MessageMap)[name]
        return undefined
    }, map)
    return typeof value === 'string' ? value : key
}

export function t(key: string, params?: MessageParams): string {
    const lang = useLocaleStore.getState().lang
    let message = resolve(messages[lang], key)
    if (message === key && lang !== 'zh-CN') message = resolve(messages['zh-CN'], key)
    if (params) {
        for (const [name, value] of Object.entries(params)) {
            message = message.replaceAll(`{${name}}`, String(value ?? ''))
        }
    }
    return message
}

export function useTranslation() {
    const lang = useLocaleStore((s) => s.lang)
    return { t, lang }
}

export function localeTag(lang: Lang): string {
    return lang === 'zh-CN' ? 'zh-CN' : 'en-US'
}
```

```ts
const store = new Map<string, string>()
const localStorageMock: Storage = {
    get length() {
        return store.size
    },
    clear: () => store.clear(),
    getItem: (key) => store.get(key) ?? null,
    key: (index) => Array.from(store.keys())[index] ?? null,
    removeItem: (key) => store.delete(key),
```

## Notes / deviations from the spec (intentional, YAGNI)

1. **MUI theme locale — omitted.** `@mui/material/locale` is not present in the installed MUI version, and the app uses no locale-sensitive MUI components (no DatePicker/DataGrid/Calendar), so applying a MUI locale would have zero visible effect while adding import risk. The theme stays static. The visible "component/locale follows language" requirement is satisfied by locale-aware date formatting (`toLocaleString(localeTag(lang))`) and `<html lang>`. Revisit if a locale-sensitive MUI component is introduced.
2. **`moment.locale()` — omitted.** The only `moment` usage (`Clock`) renders the locale-independent `HH:mm`/`HH:mm:ss` format, so switching `moment`'s locale has no visible effect and would needlessly import locale bundles. Omitted for the same YAGNI reason.
3. **`colorMode.system` wording unified.** `HomeFloatingActions` previously labeled system mode "自动" while `ColorModeSelector` used "跟随设备"; both now resolve to `colorMode.system` ("跟随设备" / "System") for consistency.
